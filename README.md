# Erasmus+ Youth Opportunities

A pure static website for browsing Erasmus+ youth activities (training courses,
seminars, youth exchanges, …). It reads all project data from a local JSON file
and can be hosted on GitHub Pages with no backend, database, or build step.

Project data is collected automatically from the **SALTO-YOUTH European Training
Calendar** by a Python scraper (`scripts/sync_salto.py`) and written to
`data/projects.json`.

## What the project does

- Displays Erasmus+ youth activities from `data/projects.json`, **sorted by start date**
- Lets visitors search by keyword and filter by month, project type, destination
  country, and residence-country eligibility
- Shows each activity's **application deadline** (⌛) and tints a card light red
  once that deadline has passed
- **Hides activities whose finish date is in the past**, with a *Show past
  projects* toggle (off by default) next to the results count
- Shows **country flags** next to country names in the dropdowns and lists
- Labels online activities as **Online** in the card pill instead of a country
- Adapts the application panel to how many countries are eligible (0 → infopack
  only, 1 → direct apply, 2+ → country dropdown), and opens the correct
  application form for the visitor's country of residence
- Shows a dedicated details page for each activity
- Includes a static NGO submission page and a lightweight suggestions/feedback modal

## How data works

The site reads activity entries from `data/projects.json`. Each object:

```json
{
  "id": "proj-001",
  "salto_id": "salto-training-14710",
  "salto_url": "https://www.salto-youth.net/tools/european-training-calendar/training/...",
  "title": "Erasmus4Democracy ProjectLab",
  "ka_action": "KA153 – Youth Workers Mobility",
  "location_city": "Sofia",
  "destination_country": "Bulgaria",
  "start_date": "2026-08-31",
  "end_date": "2026-09-05",
  "application_deadline": "2026-06-15",
  "hosting_ngo": "Human Resource Development Center, Bulgaria (National Agency)",
  "infopack_url": "https://www.salto-youth.net/.../training/...",
  "summary": "A seminar on municipal youth participation and local democracy.",
  "application_forms": {
    "Greece": "https://organiser.example/apply",
    "Spain": "https://organiser.example/apply"
  }
}
```

- `application_forms` maps each eligible **country of residence** to the
  application URL (the organiser's external form when one exists, otherwise the
  SALTO activity page).
- `application_deadline` drives the ⌛ deadline line and the passed-deadline card tint.
- Dates are ISO `YYYY-MM-DD`; month-only source dates are stored as the 1st.
- When `location_city` is "Online", the catalogue pill reads **Online**.
- A project is hidden once `end_date` (or `start_date` if no end date) is in the
  past, unless the *Show past projects* toggle is on.

## Data sync (scraper)

`scripts/sync_salto.py` pulls activities from the SALTO European Training
Calendar and merges new ones into `data/projects.json`.

**What it does, step by step:**

1. Queries the calendar's HTML search with the same filters as the website —
   only activities that **start in the future** and whose **application deadline
   is still open**, ordered by deadline — and pages through the whole result set.
2. Reads each result tile directly for category (→ KA action), title, dates
   (human text → ISO), venue (city + country), application deadline and the list
   of eligible participant countries (regional labels like "Belgium - FL" are
   collapsed; "Erasmus+ Youth Programme countries" expands to all programme
   countries; partner-region groups are dropped).
3. Opens each activity page once to read the organiser name and to find a real
   external application form / infopack link in the organiser's description.
4. Maps every eligible residence country to the application URL.

**Run it locally:**

```bash
python -m venv .venv && source .venv/bin/activate   # use a fresh venv
pip install requests beautifulsoup4
python scripts/sync_salto.py
```

It only appends activities whose `salto_id` is not already present, so it is
safe to run repeatedly. The included GitHub Actions workflow can run it on a
schedule or on demand and commit the refreshed `data/projects.json`.

## NGO submission form

`submit.html` is a static-friendly submission form for NGOs.

- Ready for Formspree-style integration — replace the placeholder `action` URL
  in `submit.html` with your form service endpoint
- Repeatable country/application-form rows are managed in `js/submit.js`
- Client-side validation checks required fields, date order, and URL fields
- File uploads require a form service that supports `multipart/form-data`;
  otherwise use the Infopack URL field

## Deployment on GitHub Pages

1. Push the files to GitHub
2. Open the repository **Settings → Pages**
3. Set the source to deploy from the `main` branch, root folder, and save

## Local usage

Serve the folder with any static server (e.g. `python -m http.server`) and open
`index.html`. Opening via the `file://` protocol can trip browser security rules
for local JSON; a simple static server or GitHub Pages avoids that.

## Maintenance notes

- Styling is centralized in `css/style.css`
- Shared filtering, sorting, country/flag, and data-loading helpers are in `js/filters.js`
- Catalogue behaviour is in `js/app.js`; single-activity page in `js/project.js`
- Activity data is generated by `scripts/sync_salto.py` — edit the source there,
  not by hand, unless you are adding a one-off entry
- No build tools or package managers are required for the website itself
